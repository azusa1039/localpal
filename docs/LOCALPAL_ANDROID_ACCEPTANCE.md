## 验收流程

1. 首次打开：直接进入本地聊天页；侧栏只有新聊天、历史列表和设置。
   顶部包含侧栏按钮、对话标题、模型选择、新聊天和三点菜单。
2. 无模型：顶部模型菜单可以进入模型管理；输入区不会假装能够推理。
3. 设置 → 本地模型：下载或导入适合设备内存的真实 GGUF，观察进度、大小、
   加载状态；顶部选择模型后确认确实加载成功。
4. 离线生成：断开网络发送消息，确认回复逐步显示；生成过程中停止，确认
   推理结束、界面恢复可输入状态；再发送一条消息。
5. 历史：新建第二个对话，确认内容隔离；重命名、固定、导出和删除一个
   测试对话。强制停止并重新打开应用，确认保留的对话能够继续。
6. 角色：在个性化中创建角色，填写名称、描述、系统提示词；使用明确、
   可观察的系统要求验证模型输入，例如“每次回答以 [LocalPal] 开头”。
   选择角色开启新对话，再切回默认助手，检查角色与对话关联。
7. 生成参数：修改 temperature / top_p / top_k / penalty_repeat / n_predict，
   确认保存与再次打开一致。参数语义以现有引擎为准。
8. 导出/导入：导出测试对话并导入，检查用户和助手消息及角色关联。
9. 模型管理：卸载后输入区反映没有已加载模型；重新加载后恢复生成。
   测试模型参数、GGUF 导入、删除；支持视觉的模型另测投影模型选择。
10. 深浅色：检查普通文字、行内斜体、独立斜体段落、列表、引用、代码块、
    表格和链接；独立斜体段落分别为 #6B7280 / #9CA3AF，行内斜体保持正文色。
