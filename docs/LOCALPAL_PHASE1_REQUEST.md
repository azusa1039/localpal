# LocalPal 第一阶段开发计划（Phase 1）

## 一、项目定位

项目名称：LocalPal

基础项目：PocketPal AI

GitHub 仓库：https://github.com/azusa1039/localpal

目标平台：Android

技术基础：React Native + TypeScript + PocketPal 原有本地推理架构。

开发方式：以 Codex 为主要 AI 编程助手，采用分批开发、逐项验收、持续提交和远程备份的方式。

### 核心目标

将 PocketPal 改造成一款具有 GPT Android App 风格的本地 AI 聊天应用。

UI 设计以用户提供的 GPT App 截图和手绘草图为主要参考。

重点是复刻 GPT 的布局、交互逻辑、导航结构、菜单组织方式和视觉体验，而不是简单修改颜色或圆角。

保留 LocalPal 自身品牌，不使用 OpenAI 或 ChatGPT 官方标识，不虚构原应用不具备的云端功能。

---

## 二、第一阶段功能范围

### 1. GPT 风格聊天主界面

重新设计聊天页面，尽可能贴近 GPT Android App 的布局。

包含：

- 顶部导航栏。
- 左侧菜单入口。
- 当前对话标题。
- 当前模型显示与模型切换入口。
- 右上角新建对话按钮。
- 右上角三点菜单。
- GPT 风格的消息展示区域。
- 底部输入框。
- 附件及功能入口。
- 发送、停止生成等交互。

聊天界面需要支持流式回复，能够逐步显示本地模型生成的内容。

保留原有推理功能，不得因为 UI 改造而破坏本地模型运行。

### 2. GPT 风格侧边栏

按照 GPT App 的导航布局重新设计侧边栏。

保留：

- 新建聊天。
- 历史对话列表。
- 对话管理。
- 设置入口。

历史对话支持：

- 查看历史对话。
- 继续已有对话。
- 创建新对话。
- 删除对话。
- 对话标题管理（在原有能力基础上实现）。

不添加当前项目没有实现的云端功能。

不要为了复刻 GPT 而添加没有实际功能的菜单入口。

### 3. 顶部模型下拉菜单

将 PocketPal 原有模型选择功能融入 GPT 风格聊天顶部。

要求：

- 显示当前使用的模型。
- 点击模型名称展开下拉菜单。
- 显示已安装的本地模型。
- 支持切换模型。
- 显示模型加载状态。
- 显示必要的模型信息。
- 未安装模型时提供进入模型管理页面的入口。

模型切换必须调用原有模型管理和加载逻辑，不得只改变 UI 显示。

### 4. 三点菜单与生成设置

重新设计 GPT 风格的右上角三点菜单。

保留和整合 PocketPal 已有能力：

- 生成参数设置。
- 对话导出。
- 对话导入。
- 其他确实已经存在且适合放入该菜单的聊天操作。

生成设置需要尽可能保留原有参数：

- Temperature
- Top P
- Top K
- Repetition Penalty
- Max Tokens

具体参数以原项目实际支持情况为准，不得虚构推理引擎不支持的设置。

### 5. 模型管理页面

将 PocketPal 原有模型管理功能重新整理成符合 GPT 风格的界面。

模型管理入口放入设置页面。

保留：

- 模型下载。
- GGUF 模型导入。
- 模型加载。
- 模型卸载。
- 模型删除。
- 模型参数配置。
- 已安装模型列表。
- 模型下载进度。
- 模型大小及必要状态信息。

保留原有视觉模型及其投影模型配置能力（如果当前版本支持）。

要求：

- 重新设计模型卡片。
- 统一按钮、图标、间距和排版。
- 统一下载、加载、卸载和删除操作的视觉风格。
- 不改变原有模型文件格式及底层加载机制。
- 不丢失已有模型管理能力。

不再使用原版 PocketPal 不协调的独立功能入口堆叠方式。

### 6. 角色设定与个性化

保留角色设定能力，并将其整合到聊天和对话设置中。

第一阶段支持：

- 设置角色名称。
- 设置角色描述。
- 设置系统提示词。
- 编辑角色设定。
- 选择不同角色设定。
- 在新对话中应用角色设定。

要求角色设定能够真正影响模型输入，而不只是改变界面显示。

不在本阶段开发复杂的跨会话长期记忆系统。

### 7. 历史对话与本地数据

保留 PocketPal 原有对话存储机制。

确保：

- 对话能够本地保存。
- 退出应用后对话不会丢失。
- 可以重新打开历史对话。
- 新旧对话之间数据隔离。
- 角色设定和对应对话关联正确。

不得在 UI 改造时破坏原有数据结构。

### 8. Markdown 渲染器

这是第一阶段的重要独立任务。

完善现有 Markdown 渲染器，使其能够正确显示：

- 标题。
- 普通段落。
- 粗体。
- 斜体。
- 列表。
- 引用。
- 代码块。
- 表格。
- 链接。

特别增加独立斜体段落的次要文字颜色支持。

#### 特殊样式要求

当模型输出一个完整的独立斜体段落时，渲染器需要自动使用淡灰色文字，并保留斜体效果。

颜色：

浅色主题：
`#6B7280`

深色主题：
`#9CA3AF`

要求：

1. 仅对完整独立的斜体段落应用次要文字颜色。
2. 普通正文继续使用正常文字颜色。
3. 普通行内斜体不应自动变成灰色。
4. 不改变 Markdown 原始文本。
5. 不对模型生成内容进行语义改写。
6. 保留原有 Markdown 结构及其他渲染功能。
7. 同时支持浅色与深色主题。

由模型通过 Markdown 格式决定哪些段落使用斜体，应用渲染器只负责正确显示对应样式。

不得在本任务中加入特定角色扮演逻辑或额外的文本分类系统。

## 三、UI 设计原则

### 参考目标

以用户提供的 GPT Android App 截图和手绘草图为主要视觉依据。

不是只参考 GPT 的设计理念，而是尽可能还原其具体界面结构和交互体验。

重点包括：

- 顶部导航栏。
- 侧边栏。
- 新建聊天入口。
- 对话历史列表。
- 顶部模型下拉。
- 右上角三点菜单。
- 生成设置。
- 设置页面。
- 模型管理页面。
- 底部输入区域。

### 统一设计规范

建立统一的 UI 设计系统：

- 颜色规范。
- 字体规范。
- 间距规范。
- 圆角规范。
- 图标规范。
- 按钮规范。
- 弹出菜单规范。
- 浅色与深色主题。

要求整个应用保持一致，而不是每个页面单独设计。

### 功能入口整理

保留真正需要的 PocketPal 功能。

不需要的原版入口应当从新 UI 中移除。

不实现或不展示：

- PocketPal Plus。
- 不需要的 Pals 独立入口。
- 不需要的基准测试入口。
- 未实现的插件入口。
- 未实现的项目和资料库功能。
- 未实现的定时任务功能。
- 不存在的云端 AI 功能。

不要仅为了模仿 GPT 而制造空壳页面。

---

## 四、技术实施原则

1. 使用现有 React Native + TypeScript 技术栈。
2. 优先复用 PocketPal 已有组件和业务逻辑。
3. 不随意升级依赖。
4. 不随意重构原生 Android 推理模块。
5. 不破坏 GGUF 模型加载机制。
6. 不改变现有本地模型数据存储格式。
7. UI 与业务逻辑尽可能分离。
8. Markdown 渲染逻辑独立实现并测试。
9. 不因视觉改造而删除已有可用功能。
10. 每次修改必须有明确的测试和验收结果。

## 六、Git 与备份制度

本项目必须采用持续备份策略。

建议新开发分支：

`feat/localpal-phase1-rebuild`

要求：

1. main 只作为基础代码分支，不直接修改。
2. 所有开发均在独立功能分支完成。
3. 每个 Batch 单独提交。
4. 每个 Batch 验收后立即推送 GitHub。
5. 每次推送后验证远程提交 SHA。
6. 不允许使用 force push。
7. 不允许未经确认执行 reset、clean 等破坏性操作。
8. 每个 Batch 保留修改文件清单和测试报告。
9. 建立 `docs/LOCALPAL_PHASE1_REBUILD.md` 记录进度。
10. 不允许只将成果保存在 Codex 云端工作区。
